# Deeper Connect Mini → Home Assistant

Версия **0.1.9**. 
Подтверждена успешная работа на Deeper Connect Mini с AtomOS 2.0.6.h2.

## Сущности устройства

По умолчанию интеграция создаёт восемь датчиков, одну сущность прошивки, две кнопки и пять выпадающих списков — всего 16 сущностей. Четыре списка управляют Instagram, YouTube, WhatsApp и Telegram. Дополнительные списки создаются только для сервисов, которые пользователь сам добавил через форму:

| Сущность | Назначение |
|---|---|
| Active tunnels | Число туннелей с хотя бы одним активным IP |
| AtomOS firmware | Текущая и доступная версии; наличие обновления |
| AtomOS version | Установленная версия AtomOS |
| CPU cores | Число ядер |
| CPU model | Модель CPU |
| Latest AtomOS version | Последняя доступная версия AtomOS |
| Temperature | Температура, по умолчанию °C; единицы выбираются в настройках датчика |
| Total memory | Общий объём памяти в MiB |
| Whitelist domains count | Число доменов в routing whitelist |
| Refresh and repair tunnels | Ручное обновление активных туннелей и восстановление маршрутов |
| Restart device | Ручная перезагрузка Mini |
| Routing mode | Общий режим Direct / Smart / Full |

Для Instagram, YouTube, WhatsApp и Telegram доступен один выпадающий список на приложение. Восемь прежних кнопок приложений убраны, их записи очистятся при загрузке. Все приложения из каталога автоматически не добавляются. Сущностей отдельных туннелей, IP-адресов и версий сигнатур в интерфейсе нет. Внутренние API приложений и доменов сохраняются для фонового восстановления маршрутов.

При первой успешной загрузке новой версии записи удалённых сущностей этой интеграции очищаются из реестра Home Assistant. Запрошенные сущности сохраняют unique_id, существующие entity_id и настройки. Сущности других устройств и интеграций не затрагиваются.

## Установка и обновление

1. Замените папку `/config/custom_components/deeper_connect` папкой из архива. Файл `manifest.json` должен находиться непосредственно в ней. При замене уберите старые `switch.py` и `services.yaml`, которых больше нет в пакете. Новый `select.py` содержит общий режим устройства и четыре маршрута приложений. Русская локализация поставляется в `translations/ru.json`.
2. Перезапустите Home Assistant. Удалять и заново добавлять настроенную интеграцию не нужно.
3. Для новой установки: **Настройки → Устройства и службы → Добавить интеграцию → Deeper Connect**. Укажите `http://34.34.34.34/api`, логин и обычный пароль AtomOS.

Сохранённые учётные данные предыдущих версий продолжают работать. При настройке, повторной авторизации и перенастройке вводите обычный пароль — шифрование выполняется автоматически. Обычный пароль не сохраняется; в конфигурации хранится шифротекст для API.

## Локализация и раздел Configuration

Названия сущностей, формы подключения/настроек и добавления сервисов и варианты маршрутов доступны на русском и английском. Названия сущностей используют штатные `translation_key` Home Assistant. Динамические названия стран, общая/прямая маршрутизация, отметка недоступного туннеля и три общих режима выбирают язык по системному языку Home Assistant: **Настройки → Система → Общие → Язык**. Для других языков используется английский.

Кнопка **Refresh and repair tunnels** переименована и перенесена в **Configuration / Настройки** на странице устройства. На русском она называется **Обновить и восстановить туннели**. Её unique_id и существующий entity_id сохраняются, поэтому переименование не требует менять автоматизации. Пользовательские имена, заданные вручную, сохраняются; чтобы увидеть перевод, сбросьте пользовательское имя сущности.

После обновления перезапустите Home Assistant. Если интерфейс продолжает показывать старые названия, обновите страницу браузера.

## Форма добавления сервисов

Откройте **Настройки → Устройства и службы → Deeper Connect → Настроить**. Теперь здесь меню:

- **Опрос и автоматическое восстановление** — прежние настройки интервалов и разрешения автоматизации.
- **Выбрать приложение** — выбрать любое приложение из каталога вашего Deeper, затем назначить прямой маршрут, общую маршрутизацию или доступный туннель. После сохранения настройка применяется на устройстве и появляется отдельный список маршрутов приложения. Четыре прежних приложения сохраняются.
- **Добавить свой сервис** — ввести название, от 1 до 50 доменов и маршрут. Все домены сервиса получают выбранный туннель либо прямой маршрут. На странице устройства появляется один список маршрутов для всей группы.

Пример собственного сервиса:

```text
Название: Мой сервис
Домены:
example.org
cdn.example.org
Маршрут: Германия (DE)
```

Название — подпись в Home Assistant, а маршрутизация определяется указанными доменами. Само по себе произвольное имя не добавляет приложение в каталог AtomOS. Вводите домены, без `https://`, путей, портов, IP-адресов и `*`. Допустимы международные домены; они переводятся в IDNA. Домены можно разделять строками, запятыми или точками с запятой. Автоматического определения связанных доменов приложения нет.

Сохранение собственного сервиса добавляет отсутствующие правила в routing whitelist через `POST /smartRoute/addToWhitelist/domain` и меняет существующие через `/smartRoute/editWhiteEntry/domain`. Поэтому указание уже настроенного домена явно меняет его существующий маршрут. API добавления найден в исходном [Deeper Tools](https://greasyfork.org/en/scripts/527972-deeper-tools/code), с параметрами `domainName` и `tunnelCode`; на пользовательском Mini этот новый API ещё не проверялся.

Для собственного сервиса доступны прямое подключение и конкретные доступные туннели. «Общая маршрутизация» для группы доменов пока не реализована, так как для неё требуется удаление доменных правил, а не назначение `ZZ`. Имена собственных сервисов не должны повторяться, один домен не может принадлежать двум созданным здесь сервисам.

Если домены одной группы имеют разные маршруты, список покажет **Разные маршруты**. Это индикатор состояния; выберите конкретный маршрут, чтобы объединить настройки всех доменов. При частично выполненной команде повторное сохранение перечитывает устройство и пропускает уже применённые правила. Все выбранные приложения и группы доменов сохраняются после перезапуска; настройка формы не включает фоновое обновление сама по себе.

Удаление собственных сервисов и редактирование состава доменов через форму пока не реализованы. Маршрут добавленного сервиса меняется его выпадающим списком. Удалять правила напрямую можно через AtomOS.

## Температура и иконки

Датчик получает температуру в °C и рекомендует отображение в °C по умолчанию, независимо от общей системы единиц HA. Пользователь может изменить единицы через **Temperature → настройки сущности → единица измерения**, например выбрать °F. Используется штатное преобразование Home Assistant — значение и единицы изменяются вместе, повторного ручного пересчёта нет. Если ранее для датчика были явно выбраны другие единицы, HA сохраняет пользовательский выбор; переключите на °C в настройках сущности.

У **AtomOS firmware** задан тип Firmware и значок микросхемы `mdi:chip`.

Остальные иконки проверены по [официальному каталогу Material Design Icons](https://github.com/Templarian/MaterialDesign):

## Автоматическое восстановление маршрутов

**По умолчанию запуск только ручной**, кнопкой **Refresh and repair tunnels**. При обновлении с версии 0.1.4 прежнее включённое расписание тоже отключается. Оно не запустится снова, пока пользователь явно не включит его в новой форме настроек.

Если автоматизация нужна, откройте **Настройки → Устройства и службы → Deeper Connect → Настроить → Опрос и автоматическое восстановление**:

- Включите **Автоматически обновлять туннели и восстанавливать маршруты**.
- Укажите **Интервал автовосстановления (минуты)**: от 5 до 1440 минут, по умолчанию 60. Например 15 — каждые 15 минут, 60 — каждый час, 240 — каждые четыре часа.
- **Интервал опроса (секунды)** отвечает только за чтение датчиков и режима, по умолчанию 60 секунд. Этот опрос не обновляет туннели и не меняет правила.

Выбранное пользователем новое расписание сохраняется после перезапуска. Первый запуск произойдёт через указанный интервал после загрузки или перенастройки; немедленного фонового восстановления при загрузке нет. Отключение опции отменяет расписание и ожидающие задачи через перезагрузку интеграции.

И ручной, и разрешённый автоматический запуск:

1. Перечитывает туннели и обновляет каждый туннель с активными IP.
2. Ждёт 60 секунд, пока Deeper обновит IP.
3. Заново читает туннели и текущие правила приложений/доменов.
4. Переназначает только правила, которые ссылаются на недоступные туннели, выбирая доступный маршрут по приоритетам исходного модуля.

Работающие маршруты и специальные режимы `LL`/`ZZ` не переназначаются. YouTube, Netflix и Plex исключены из автоматического переназначения. Если доступных туннелей нет, новые назначения не выполняются. Перекрывающиеся запуски блокируются; при выгрузке или перезагрузке Mini ожидающее восстановление отменяется.

## Выпадающие списки приложений

Для **Instagram, YouTube, WhatsApp, Telegram** и приложений, добавленных через форму, доступен один список маршрутов приложения:

- **Direct connection** — прямой маршрут `LL`, выключение DPN для данного приложения.
- **General routing** — удалить индивидуальное правило (`ZZ`) и следовать общей маршрутизации устройства. Этот вариант сам по себе не гарантирует прямое соединение.
- **Страна (код туннеля)** — назначить конкретный доступный DPN-туннель, например **Sweden (SE)** или **Germany (DE)**.

В списке отображается текущее назначение, а в атрибутах — `current_tunnel`. Список доступных туннелей обновляется при обычном опросе. Если текущий маршрут недоступен, он остаётся видимым с отметкой **unavailable**; заново назначить его нельзя. Вместо него можно выбрать доступную страну, прямое подключение или общую маршрутизацию.

Перед каждой командой правила и туннели перечитываются с Deeper, поэтому отключившийся после открытия списка туннель не будет назначен. Выбор назначает настоящий `tunnelCode`, а не код страны. Если приложение отсутствует в ответе AtomOS, его список недоступен. Общий режим устройства не меняется. Исключение YouTube из фонового восстановления не мешает ручному выбору его маршрута.

## Перезагрузка устройства

На странице устройства нажмите **Restart device**. Используется `POST /api/admin/reboot`, найденный в исходном Deeper API-клиенте. После принятой команды сущности временно становятся недоступны; обычный опрос восстановит их после запуска Mini. Подготовленные учётные данные продолжают использоваться для нового входа.

Команда отправляется один раз. Если устройство оборвёт соединение до подтверждения, Home Assistant сообщит, что результат неизвестен; команда автоматически не повторяется. Ошибки авторизации или явный отказ API отображаются как ошибки. Реальная перезагрузка пользовательского Mini в ходе разработки не выполнялась.

## Режим маршрутизации

**Routing mode** предлагает три значения:

- **Direct** → `dpnMode: disabled`.
- **Smart** → `dpnMode: smart`, туннель из `smartTunnel` устройства.
- **Full** → `dpnMode: full`, туннель из `fullTunnel` устройства.

Используются подтверждённые пользователем `GET /api/smartRoute/getDpnMode` и `POST /api/smartRoute/setDpnMode`. Страна не выбирается автоматически: сохраняется соответствующий туннель, настроенный на самом Deeper. В атрибутах выбора видны текущий, Smart- и Full-туннели. Если у Full-туннеля нет активных IP, включение Full завершается ошибкой, вместо назначения другой страны. Для изменения страны Full/Smart пока используйте интерфейс AtomOS.

На списках приложений используются их иконки; для Telegram — бумажный самолёт.

## Где находится код

- `custom_components/deeper_connect/__init__.py`: регистрация таймера `async_track_time_interval`, проверка настройки `auto_refresh` и интервал `refresh_interval_minutes`. Старое расписание требует повторного разрешения в новых настройках.
- `custom_components/deeper_connect/coordinator.py`: методы `refresh_all` и `_refresh_all` — обновление туннелей, ожидание и применение исправлений.
- `custom_components/deeper_connect/policy.py`: `repair_plan` — поиск недоступных маршрутов и выбор замен.
- `custom_components/deeper_connect/config_flow.py`: форма настроек интервалов.

## Обновления AtomOS

`AtomOS firmware` показывает наличие новой версии. Последняя версия кешируется на шесть часов; текущая версия и температура читаются при обычном опросе. Установка прошивки через Home Assistant не реализована; обновляйте через штатный интерфейс AtomOS.

## Пароль для API

Используется UTF-8 → RSA-OAEP с SHA-1 и MGF1/SHA-1 → Base64. Функция и публичный ключ найдены в [Deeper API-клиенте](https://github.com/jerry-yu/deeper-device-mcp/blob/master/src/functions.ts) и [public.ts](https://github.com/jerry-yu/deeper-device-mcp/blob/master/src/public.ts). Алгоритм соответствует настройкам [Node.js publicEncrypt](https://nodejs.org/api/crypto.html#cryptopublicencryptkey-buffer). Python/Node.js совместимость проверена в обе стороны.

## Проверки

Успешно пройдены **98 проверок**, включая отключение прежнего расписания при обновлении, пользовательские интервалы в минутах, сохранение Smart/Full-туннелей, отправку перезагрузки без повторов и ручной выбор маршрутов приложений и очистку старых кнопок. Назначение маршрутов проверено на тестовом API; новые выпадающие списки нужно проверить в вашем Home Assistant. Дополнительно проверены формы добавления приложений и собственных сервисов, валидация доменов и IDNA, сохранение настроек, добавление/изменение доменных правил и повторное сохранение без повторных операций. Тесты проверяют шифрование, HTTP-клиент, cookie авторизации по IP, обновление сессии, пагинацию доменов, обработку ошибок, маршрутизацию, свежесть правил после ожидания, запрет перекрывающихся запусков, отмену при выгрузке и границы очистки старых сущностей. Проверки логики Home Assistant используют минимальные подставные классы: это не проверка загрузки настоящих платформ HA.

Для запуска в отдельном окружении нужны `aiohttp` и `cryptography`; тест совместимости с Node.js использует `node`, если он установлен:

```sh
python -m unittest discover -s tests -v
```

Тестовый HTTP-сервер слушает только 127.0.0.1; проверки не обращаются к вашему Deeper.
